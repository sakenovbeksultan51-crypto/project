# Помощник TableFlow

В рабочем пространстве появился раздел «Помощник». Он получает новый снимок смены при каждом вопросе: состояния отслеживаемых столов, количество гостей в очереди, среднее время посещения, прогноз ухода, байесовские вероятности и наиболее загруженный час за последние 8 часов по сохранённой истории.

Видео, адрес камеры, имена гостей, заметки и исходный журнал событий не включаются в контекст модели. Помощник не изменяет состояние зала. История чата сохраняется при переходах между разделами, но очищается при обновлении страницы, смене режима или сбросе смены.

## Локальная LLM через Ollama

В текущей локальной копии официальный консольный модуль Ollama 0.40.16 с CPU/Vulkan находится в `.data/ollama-runtime` (не входит в Git). При `npm run dev` скрипт `scripts/ensure-ollama.mjs` проверяет локальный сервер и при необходимости запускает его в фоне. Он использует адрес `127.0.0.1:11434`, отключает облачные функции для этого запуска и пишет журнал в `.data/ollama-server.log`. Уже запущенная Ollama переиспользуется. Модель хранится в стандартной папке пользователя `.ollama/models`.

На другом компьютере можно установить обычную Ollama:

1. Установите [Ollama для Windows](https://ollama.com/download/windows).
2. Загрузите модель командой `ollama pull qwen2.5:3b`. Скачивание выполняется отдельно; TableFlow не скачивает модель автоматически.
3. Оставьте Ollama запущенной. Если установлена одна текстовая модель, TableFlow выберет её автоматически.
4. Откройте «Помощник» и нажмите «Проверить подключение».

Для явного выбора модели скопируйте `.dev.vars.example` в `.dev.vars`, задайте `ASSISTANT_PROVIDER=ollama`, `OLLAMA_BASE_URL` и `OLLAMA_MODEL`, затем перезапустите `npm run dev`. Локальный адрес по умолчанию — `http://127.0.0.1:11434`. При размещении сайта на другом компьютере этот адрес относится к серверу сайта, а не к компьютеру посетителя.

Используются официальные методы Ollama [GET /api/tags](https://docs.ollama.com/api/tags) и [POST /api/chat](https://docs.ollama.com/api/chat) с `stream: false`.

## OpenAI API

Задайте в серверном `.dev.vars`:

```dotenv
ASSISTANT_PROVIDER=openai
OPENAI_API_KEY=ваш-собственный-ключ
OPENAI_MODEL=идентификатор-доступной-вам-модели
```

Перезапустите сервер сайта. Ключ не вводится в браузере и не передаётся клиенту. Для размещённого сайта эти значения задаются как серверные переменные окружения. Используется [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) с `store: false`. Запросы могут тарифицироваться провайдером.

Без доступной модели помощник честно переключается в «Режим сводок»: отвечает по текущим данным на типовые вопросы. Это обработка запросов по правилам, а не LLM или генеративный ИИ. Если подключённая модель перестаёт отвечать, также показывается явное уведомление и локальная сводка.

## Байесовский прогноз

`bayesianForecast` в `src/lib/table-forecast.ts` оценивает `P(T ≤ e+h | T > e)` для горизонтов 5, 10 и 15 минут. Здесь T — длительность визита, e — уже прошедшее время, h — горизонт прогноза.

Используется апостериорное предиктивное распределение процесса Дирихле с экспоненциальной базовой мерой и весом двух условных посещений. Среднее базового распределения оценивается по истории зала, поэтому это эмпирический Байес. Для расчёта берётся история конкретного стола после трёх его посещений; раньше используется история зала.

Ненормированная функция выживания:

```text
S(t) ∝ 2 × exp(−t / meanHall) + count(duration > t)
P(уход за h | гости ещё сидят) = 1 − S(e+h) / S(e)
```

Без завершённых посещений проценты не выдаются. Если в выборке меньше 10 визитов или меньше трёх визитов дольше текущего, оценка предварительная. Когда более длинных визитов нет, результат опирается на начальную модель. Это предположение модели, а не измеренная точность или гарантия. Уборка после ухода в прогноз не входит. Обе новые темы описаны в лаборатории ИИ: неделя 06 и неделя 10.
