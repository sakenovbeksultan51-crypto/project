# Telegram и контроль обслуживания

Уведомления используют сохранённую рабочую смену, а не таймер открытой вкладки. Демо-смена исключена. Новая смена по умолчанию использует 3 минуты для первого подхода и 5 минут для завершения уборки. Существующие настройки сохраняются; изменить их можно в разделе «Настройки».

## Подключение

1. В своём Telegram создать бота через `@BotFather` → `/newbot`.
2. Добавить токен в Vercel-проект **app**, Production, переменная `TELEGRAM_BOT_TOKEN`. Токен нельзя публиковать в GitHub или вставлять в интерфейс сайта.
3. Выполнить Redeploy после изменения переменной. `TELEGRAM_WEBHOOK_SECRET` и `NOTIFICATIONS_CRON_SECRET` уже настроены при развёртывании модуля.
4. На сайте открыть «Настройки → Уведомления в Telegram → Подключить Telegram». Открыть полученную ссылку и нажать Start. Ссылка одноразовая, действует 10 минут и связывает именно текущую браузерную сессию.
5. Нажать «Проверить уведомление» и убедиться в доставке.

Webhook регистрируется при создании ссылки подключения. Он проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`. Текущая версия рассчитана на личный чат сотрудника; группы пока не поддерживаются.

## Фоновая работа

Upstash QStash Free вызывает `/api/notifications/dispatch` раз в две минуты. Это около 720 штатных доставок в день из лимита 1000; повторные доставки при ошибках тоже учитываются. Запрос проверяется по подписи QStash либо серверному секрету. Настройка расписания: `node scripts/setup-notifications.mjs` после получения production environment. Локальный файл `.vercel/notification-secrets.json` исключён из Git и не должен публиковаться.

После порога возможна дополнительная задержка примерно до двух минут плюс время сети. Повторное напоминание отправляется не чаще раза в пять минут. Одновременные обработчики используют оптимистическую блокировку и аренду доставки на 90 секунд. При ошибке отправка повторяется позже. Telegram не предоставляет идемпотентный ключ для sendMessage: редкое дублирование при сбое сразу после отправки полностью исключить нельзя.

Кнопки «Официант подошёл» и «Уборка завершена» меняют сохранённую смену с проверкой версии. Действия от другого чата и устаревшие кнопки предыдущего посещения отклоняются. «Беру задачу» сохраняет исполнителя, но не закрывает задачу. Сайт получает серверные изменения, когда нет несохранённых локальных правок; при конфликте требуется загрузить свежую смену.

Таймер уборки начинается с перехода в «Нужна уборка». Переход в «Уборка» не сбрасывает срок. Задача закрывается при завершении уборки или изменении состояния. Таймер первого подхода закрывается подтверждением подхода или уходом гостей.

Камера и распознавание должны оставаться включёнными, чтобы появлялись новые наблюдения. Сервер способен контролировать уже сохранённые события после закрытия страницы, но не продолжает браузерное распознавание видео.

## Проверка

`node --import tsx --test tests/telegram-notifications.test.ts` проверяет реальные SQL-запросы через SQLite: таймеры, конкурирующие отправки, повторные уведомления, привязку, подтверждение, чужие и устаревшие кнопки. Без реального токена и личного чата доставка в Telegram не считается проверенной.
