# Эксперимент дообучения

Реально выполнено 4 эпохи обучения YOLOv8n на CPU. Из COCO128 детерминированно выбраны 96 изображений train и 32 validation. Метрики, seed, поимённое разделение и выбранные веса — report.json. Контрольная часть не участвовала в обновлении весов. Эти данные могли участвовать в исходном предобучении YOLO, поэтому это не независимая оценка обобщения.

Результат по классу person:

| Показатель | До | После |
|---|---:|---:|
| Recall | 0.6316 | 0.6667 |
| Precision | 1.0000 | 0.8395 |
| mAP50 | 0.7552 | 0.7136 |
| mAP50–95 | 0.5649 | 0.5320 |

Полнота немного выросла, но суммарное качество ухудшилось. В сайт вошли предобученные веса YOLOv8n и обработка увеличенных областей, а не ухудшенная дообученная версия. Реальный checkpoint эксперимента сохранён в checkpoints/finetuned.pt. Замена прежней лёгкой COCO-SSD на YOLO отдельно проверена настоящим запуском ONNX Runtime: при пороге 0.30 на контрольном bus.jpg старая модель нашла 3 человека, YOLO — 4. Один кадр не является оценкой точности на ресторане.

COCO128: https://docs.ultralytics.com/datasets/detect/coco128/ . Этот маленький набор подходит для эксперимента и отладки, но недостаточен для специализированного детектора сидящих гостей. CrowdHuman и WiderPerson могли бы дополнить перекрытия/мелкие фигуры; они не скачивались и не использовались в этом запуске. Для целевого обучения нужны реальные кадры из ресторана с рамками людей, особенно сидящих, далёких и перекрытых, а также пустые кадры. Делить данные нужно по роликам/камерам, чтобы соседние кадры не попали одновременно в train и test.

## Повторение

Python 3.12, PyTorch 2.5.1 CPU. Установить torch/torchvision из https://download.pytorch.org/whl/cpu, остальные зависимости из requirements.txt. В папку, указанную TABLEFLOW_TRAIN_DIR, поместить yolov8n.pt из официального релиза и распакованный coco128/.

```sh
TABLEFLOW_TRAIN_DIR=/path/to/training python ml/train.py
```

Используется собственный DetectionTrainer, сохраняющий исходную архитектуру полного checkpoint при создании модели. Это предотвращает потерю части весов из-за различий конструктора головы между версиями Ultralytics. Эмпирическая матрица метрик и решение выбора не заменяют тест на видео пользователя.

Лицензия YOLOv8 и производных весов: AGPL-3.0, текст находится в public/models/yolo/LICENSE. Исходный код проекта и обучение находятся в этом репозитории. ONNX Runtime: MIT.

## Повторное обучение для уменьшения ложных срабатываний

`train_precision.py` использует другой набор — выборку COCO2017 val из официального зеркала Ultralytics. Сначала все изображения делятся по наличию людей и контексту мебели (chair/couch/dining table); затем из непересекающихся частей выбираются 768 train и 192 validation. Train: 512 кадров с людьми и 256 без людей. Validation: 96 с людьми и 96 без людей. В каждой части добавлены изображения с мебелью. Все исходные 80 классов размечены как в источнике, поэтому стулья и столы не объявляются людьми. Наличие мебели не гарантирует сидящую позу человека. Это не официальный COCO benchmark: часть исходного val2017 сознательно используется для обучения, остаток для выбора модели.

6 эпох, 640 px, CPU, seed 20261107, AdamW 5e-5, заморожены первые 22 слоя. На validation сравниваются TP/FP/FN по person при фиксированных confidence=.45 и IoU=.5. Правило выбора: FP строго меньше, precision не хуже, recall падает максимум на 0.02. Иначе активные веса сохраняются. Результат — `precision-report.json`, перечень файлов — `precision-manifest.json`, обученные веса — `checkpoints/precision-finetuned.pt`. Исходные данные пользовательской камеры в обучение не входили.

Для повторения поместить `coco2017val.zip` и `yolov8n.pt` в TABLEFLOW_TRAIN_DIR и запустить:

```sh
TABLEFLOW_TRAIN_DIR=/path/to/training python ml/train_precision.py
```

Датасеты:

- COCO: https://cocodataset.org/ — общие сцены, люди и фон; использован в новом эксперименте. Скачать архив с картинками и YOLO-разметкой: https://github.com/ultralytics/assets/releases/download/v0.0.0/coco2017val.zip
- CrowdHuman: https://www.crowdhuman.org/download — взаимные перекрытия людей; рекомендован для следующего этапа, в этом эксперименте не использован.
- WiderPerson: http://www.cbsr.ia.ac.cn/users/sfzhang/WiderPerson/ — разнообразные сцены с пешеходами; в этом эксперименте не использован.
- Для конкретной камеры полезнее всего отдельный набор кадров этого зала: все люди размечены целиком, включая сидящих и перекрытых; пустые стулья, одежда и отражения оставлены как фон. Train/test делятся по роликам, а не соседним кадрам.

Заморозка весов не замораживает BatchNorm-буферы в режиме train. Дополнительный скрипт `restore_frozen_stats.py` восстанавливает running statistics только замороженных слоёв 0–21 из исходной модели, без новых шагов обучения, и сравнивает best/last. Затем `calibrate_precision.py` проверяет пороги .40 и .35 для best с восстановленными статистиками. Эти измерения используются для выбора пары «веса + порог» на validation; независимым тестом они не являются. Исходное сравнение при .45 остаётся в отчёте, поэтому изменение порога явно видно. Все промежуточные результаты и правило допуска сохраняются. Повторение дополнительных этапов:

```sh
TABLEFLOW_TRAIN_DIR=/path/to/training python ml/restore_frozen_stats.py
TABLEFLOW_TRAIN_DIR=/path/to/training python ml/calibrate_precision.py
```


Итог нового запуска: базовая модель при пороге .45 — TP 213, FP 15, FN 194 (precision .9342, recall .5233); best после обновления весов — TP 196, FP 13, FN 211. После восстановления статистик frozen backbone: best — TP 200, FP 5, FN 207; last — TP 191, FP 4, FN 216. Ни одна версия не прошла порог допуска по recall. Калибровка best на .40 дала TP 212, FP 16, FN 195; на .35 — TP 230, FP 23, FN 177, поэтому они также отклонены. Активными остались исходные веса. Исправления обработки применены отдельно: на 11 двухчеловечных сценах old detail TP/FP/FN=20/28/2, new balanced=19/1/3. Это проверка обработчика с фиксированными исходными весами; результаты не переносятся автоматически на ресторан пользователя.


## Поиск дальних столов

`train_tables.py` дообучает исходную YOLOv8n с сохранением всех 80 классов COCO. Из COCO2017 val выделены 512 обучающих изображений (288 со столами), 128 проверочных и 128 отложенных. Изображения из предыдущего эксперимента проверки людей исключены. Выполнены 4 эпохи на CPU, 640 px, AdamW 5e-5; первые 22 слоя и их статистики BatchNorm заморожены. Мелким считается стол с рамкой менее 2% площади кадра. Весов конкретной камеры и видео ресторана пользователя в обучении не было.

`benchmark_table_tiles.py` сравнивает полный кадр и четыре увеличенных перекрывающихся участка; это проверка обнаружений в отдельных кадрах до расширения зон и подтверждения во времени. На отложенной выборке исходная модель с участками нашла 30 столов, выдала 10 лишних рамок и пропустила 75 столов; дообученная — 33, 10 и 72 соответственно. Обе пропустили все 33 мелких стола. На проверочной выборке дообученная модель обнаружила 1 из 17 мелких столов против 0 у исходной. Поэтому `select_table_pipeline.py` сохранил исходные веса: критерий улучшения для мелких столов на обеих выборках не выполнен. Подробности и ограничения — `table-report.json` и `public/models/yolo/table-search-report.json`. Эти изображения могли входить в исходное предобучение; отложенная выборка также использовалась для проверки способа поиска. Это не независимая оценка для ресторана.

Файл `checkpoints/table-finetuned.pt` содержит результат эксперимента. Для повторения нужны `coco2017val.zip` и `yolov8n.pt` в `TABLEFLOW_TRAIN_DIR`, затем `python ml/train_tables.py`, четыре запуска `ml/benchmark_table_tiles.py` для пар validation/test и baseline/trained и `python ml/select_table_pipeline.py`. Параметры запуска и пути заданы в скриптах.
